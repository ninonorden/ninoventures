How to find Shopify stores using a specific app (and turn it into a lead list)

If you sell to Shopify merchants, as an app developer, an agency or a freelancer, the best lead is a store that already uses a tool like yours, or just stopped using it. A store running a competitor's reviews app has a reviews budget. A store that uninstalled it last week is actively looking.

This guide shows a repeatable workflow:

  1. Build a list of candidate store domains
  2. Detect the apps, theme and stack of every store in bulk
  3. Filter for the app you care about
  4. Turn on monitoring to catch installs and uninstalls
  5. Use the data responsibly

We'll use the Shopify App & Theme Detector on Apify. It costs $0.005 per analyzed store ($5 per 1,000), and non-Shopify, unreachable and duplicate domains are free.

How app detection works (and its limits)

Shopify apps leave fingerprints in a store's public storefront: script tags from the app's CDN (for example klaviyo.com, judge.me, rechargecdn.com), theme app extension "app embeds", and web pixels. The detector loads each store's public homepage and matches it against 130+ app signatures. It also auto-detects app embeds, even for apps that aren't in the signature list.

Limits to keep in mind:

  • Back-office apps are invisible. Apps that never touch the storefront (accounting, inventory, some fulfillment tools) can't be detected from outside. No tool can see them without store access.
  • Some apps only load on product or cart pages. Homepage detection catches the vast majority of marketing, reviews, subscription, upsell and support apps, but not 100%.
  • Password-protected and blocked stores are reported as such, and you aren't charged for them.

Step 1: Build a list of candidate stores

The detector analyzes the domains you give it, so start with a list. Good sources:

  • Your niche. Brands in "sustainable fashion", "coffee" or "pet supplies" from marketplace lists, award lists, Instagram shops and "best X brands" articles. Many DTC brands run on Shopify.
  • Search engines. Queries like "powered by shopify" coffee or site:myshopify.com <niche> surface stores in a niche.
  • Your existing CRM or a purchased company list. Enrich domains you already have.
  • Public datasets. Common Crawl or open e-commerce domain lists, if you want large volumes.

Don't worry about cleaning the list. Non-Shopify domains come back as isShopify: false and cost nothing.

Step 2: Detect apps in bulk

No code: open the Actor page, paste domains into Store URLs or domains and click Start. A typical store takes 1–3 seconds. Download the result as CSV, Excel or JSON.

With code (Node.js, npm i apify-client):

import { ApifyClient } from "apify-client";

const client = new ApifyClient({ token: process.env.APIFY_TOKEN });

const run = await client.actor("ninoventures/shopify-app-tech-detector").call({
  stores: ["allbirds.com", "tentree.com", "deathwishcoffee.com", "colourpop.com"],
  countProducts: true,
});

const { items } = await client.dataset(run.defaultDatasetId).listItems();
console.log(items.length, "stores analyzed");

Python (pip install apify-client):

from apify_client import ApifyClient

Step 3: Filter for the app you care about

Say you build a reviews app and want stores that use Judge.me or Yotpo, sell in USD and have a real catalog:

const TARGET_APPS = ["Judge.me", "Yotpo"];

const leads = items
  .filter((s) => s.isShopify && s.status === "ok")
  .filter((s) => s.apps?.some((a) => TARGET_APPS.includes(a.name)))
  .filter((s) => s.currency === "USD" && (s.productCount ?? 0) >= 50)
  .map((s) => ({
    store: s.storeName,
    domain: s.domain,
    uses: s.apps.filter((a) => TARGET_APPS.includes(a.name)).map((a) => a.name).join(", "),
    products: s.productCount,
    theme: s.theme?.name,
    instagram: s.socialLinks?.instagram ?? "",
  }));

console.table(leads);

Other useful filters:

  • By category, not brand: s.appCategories.includes("Subscriptions") finds every store with any subscription app.
  • Gaps: stores with a high productCount but no reviews app are prospects for one.
  • Stack fit: theme.isCustomTheme signals a bigger brand with a dev team. A Theme Store theme signals a smaller merchant.
  • Catalog size and price range to estimate store size and AOV.

Step 4: Monitor installs and uninstalls (the best signal)

A static list tells you who uses an app. Changes tell you who is deciding right now.

  1. Enable Monitoring mode and set a Monitoring storage name (for example reviews-competitors).
  2. Run once to save a baseline.
  3. Schedule the Actor daily or weekly with the same store list.
  4. Enable Output only stores with changes to get a pure change feed. You're not charged for unchanged stores.

Every changed row then includes:

"monitoring": {
  "appsInstalled": ["Rebuy"],
  "appsRemoved": ["Privy"],
  "themeChanged": null,
  "hasChanges": true
}

Pipe that into Slack, Google Sheets, Make, Zapier or a webhook through Apify integrations, and you get an alert the day a store drops your competitor.

Step 5: Use the data responsibly

The detector only reads public storefront pages, the same thing any visitor's browser sees. It respects robots.txt if you enable that option, and it doesn't log in anywhere. How you use the results is up to you:

  • Outreach rules differ by country. B2B email to companies is regulated by laws like GDPR and ePrivacy in the EU/UK and CAN-SPAM in the US. Use public business addresses, be relevant, identify yourself and make opting out easy.
  • Lead with value. "I noticed you recently switched reviews apps, here's a migration guide" works far better than a generic pitch.
  • Don't hammer stores. Reasonable concurrency is the default.
